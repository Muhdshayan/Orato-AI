Detailed Explanation of the ASR Module: Fluency and Pace
The ASR (Automatic Speech Recognition) module is detailed in Sections 1.4, 2.2.4, 2.1.3.5, and 3 (e.g., FR10-FR12, UC-05). It's part of the "Accent-Aware ASR & Speech Metrics" module, which processes extracted audio to generate timestamped transcripts and metrics. It's optimized for Pakistani English accents (e.g., via customized models like those in reference [3]). The module uses ASR models to transcribe speech, then analyzes it for quality metrics.
Pace (Speech Rate)

Definition from Report: Pace refers to "speech rate," calculated as words per minute (WPM) or syllables per second. It's a "Must" requirement (FR11) and includes timestamps for events.
How It's Calculated (Detailed Explanation):

Input: The audio stream (extracted during preprocessing, UC-03) is fed into an accent-aware ASR model (e.g., fine-tuned on Pakistani English datasets to handle variations like rolled 'r's or vowel shifts).
Transcription: The ASR generates a timestamped transcript (e.g., "Hello [0:01-0:02], world [0:02-0:03]"), logging confidence scores for each segment.
Rate Computation: Speech rate is derived by dividing the total word count (from the clean transcript) by the total speaking duration (excluding pauses). Formula:
Speech Rate (WPM) = (Total Words) / (Total Speaking Time in Minutes).

Pauses are detected as silences >0.5-1 second (stored in pause_durations JSONB).
Example: If a 2-minute video has 200 words and 20 seconds of pauses, effective speaking time is 100 seconds (1.67 mins), so rate = 200 / 1.67 ≈ 120 WPM.


Thresholds and Feedback: Compared to norms (e.g., ideal 120-150 WPM for presentations). Too fast (>160 WPM) might indicate rushing; too slow (<100 WPM) suggests hesitation. Low-confidence segments (e.g., due to accent mismatches) are flagged.
Storage/Output: Stored in SpeechMetrics table (speech_rate FLOAT). In reports, it's visualized with tips like "Slow down in segments [timestamps]" if pace varies.
Extensions/Edge Cases: If speech is unrecognized (low confidence), segments are flagged for manual review. This ensures cultural adaptation, as Pakistani accents might affect rate detection in standard models.



Fluency (Fluency and Articulation Assessment)

Definition from Report: Fluency is a "Should" requirement (FR12), assessing "fluency level" and "articulation clarity." It measures smooth, natural speech flow without disruptions.
How It's Calculated (Detailed Explanation):

Input: Builds on the timestamped transcript from ASR.
Components Analyzed:

Filler Words: Counts words like "um," "uh," "like" (filler_word_count INTEGER in SpeechMetrics). High counts reduce fluency score.
Pauses: Analyzes pause_durations (JSONB array, e.g., [{"start": 5.2, "duration": 1.5}]). Excessive/long pauses (>2-3 seconds) indicate hesitation.
Articulation: Measures clarity via ASR confidence scores and phonetic analysis (e.g., how well consonants/vowels are pronounced, tuned for accents).
Flow Metrics: Detects repetitions, false starts, or disfluencies using ML (e.g., n-gram analysis or neural models like BERT for smoothness).


Scoring Formula: Fluency Score (FLOAT, 0-100) = Weighted average:

40% based on filler rate (e.g., fillers per 100 words <5 = high score).
30% on pause frequency/duration (e.g., average pause <1 sec = good).
20% on articulation (e.g., average ASR confidence >0.85).
10% on overall disfluency (e.g., repetition detection via edit distance on transcript).
Example: If fillers=10%, pauses=15% of time, confidence=0.9, disfluency low → Score ≈ 85/100.


Thresholds and Feedback: Ideal fluency >80%; low scores trigger tips like "Reduce fillers at [timestamps]" or "Practice articulation for clearer enunciation." Culturally tuned to ignore accent-induced "disfluencies" (e.g., code-switching in Pakistani English).
Storage/Output: Stored in SpeechMetrics (fluency_score, articulation_score FLOAT). Aggregated into reports with annotated transcripts.
Extensions/Edge Cases: If audio quality is poor, fluency is flagged as incomplete. This is optional ("Should"), so MVP might prioritize basic metrics.
